# SOLID Principles Checklist

> **Category**: Architecture & Patterns
> **Tags**: SOLID, OOD, Clean Code

## Policy

```
Rule: Apply SOLID Principles
Description: Maintain clean object-oriented architecture.
1. Single Responsibility: A class/module should have one, and only one, reason to change.
2. Open/Closed: Software entities should be open for extension, but closed for modification. Use interfaces and inheritance rather than modifying existing code.
3. Liskov Substitution: Child classes must be substitutable for their parent classes without breaking the application logic.
4. Interface Segregation: Clients should not be forced to depend upon interfaces they do not use. Split up large interfaces.
5. Dependency Inversion: High-level modules should not depend on low-level modules. Both should depend on abstractions.
```
